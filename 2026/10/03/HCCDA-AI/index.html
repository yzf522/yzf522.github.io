云计算基础概念

云计算是什么

按需从网络获取计算、存储、网络等资源，用完释放，按使用量付费。

大特征

按需自助 —— 自己下单，不用人工申请

广泛网络接入 —— 任何设备、任何地点都能用

资源池化—— 物理资源池化共享，多用户隔离使用

快速弹性—— 秒级扩容缩容（云的核心价值）

可计量服务 —— 用量可监控、可计费

三种服务模型
IaaS 基础设施 ECS、OBS
PaaS 平台 数据库 RDS、容器 CCE
SaaS 软件 云会议、企业邮箱

部署模型

  • 公有云：服务商提供，多租户共享，成本低（日常首选）
  • 私有云：专属自己，安全性高（政企敏感数据）
  • 混合云：公有 + 私有结合，弹性又安全（最灵活）
  • 社区云：特定行业共享（如金融行业云）

虚拟化

虚拟机 VM 容器（Docker）
内核 各自独立 OS 内核 共享宿主机内核
启动 慢（分钟级） 快（秒级）
体积 大（GB 级） 小（MB 级）
隔离 强 弱（进程级）

华为云架构层级

  1. Region（区域）：物理上独立的大区（如华南 - 广州），Region 间完全隔离

    作用：异地容灾

  2. AZ（可用区）：Region 内独立的机房（电力 / 网络独立），跨 AZ 部署 = 高可用，

    作用：本地高可用，同 Region 不同 AZ 时延低极小，不同 Region 隔离

  3. 边缘节点：靠近用户，低时延（CDN / 边缘计算）

计费模式

  • 按需计费：秒级开通，用完即停，贵 —— 适合弹性临时场景
  • 包年包月：预付费，便宜 —— 适合长期稳定负载（如官网服务器）
  • 竞价计费：超便宜但可能被回收 —— 适合无状态、可中断任务

计算服务三件套

名称 作用 考点
ELB 把请求分发到多台 ECS 支持四层 (TCP/UDP) 与七层 (HTTP/HTTPS)；
加权轮询
最少连接
IP Hash
IP Hash 做会话保持
ECS 云上的虚拟机（IaaS 核心） 属 IaaS；
镜像创建实例；
安全组 = 虚拟防火墙；
按需 / 包年包月 / 竞价计费
AS 按负载自动加 / 减 ECS 削峰填谷；
伸缩组 + 策略（定时 / 周期 / 动态）；
健康检查失败自动替换

1.ELB

  • 支持四层与七层：

    四层：按 IP + 端口原样转发，简单，速度快，适合流量转发，游戏、视频流

    七层：按 URL / 域名 / Cookie 等内容分发，稍慢一点点，适合：Web 网站、按路径分流（/api 给A，/图片 给B）

  • 加权轮询：轮流分，配置高的机器 “权重” 大、多分一点

  • 最少连接：谁手上活少（连接数少）分给谁

  • IP Hash：同一个 IP 算出来固定打同一台机器

  • 会话保持：用 IP Hash（或 Cookie）让同一用户的请求始终去同一台服务器

  • 健康检查：ELB 定期 “探活”，每隔几秒问后端：”你还活着吗？”

    没回应 → 自动从分发名单里剔除，不转给它；恢复后自动加回

2.ECS

  • 镜像：公共 / 私有 / 共享 / 市场镜像

    镜像 vs 快照：镜像是模板，快照是某个时刻的备份

  • 规格族：通用型 / 计算型 / 内存型 / 存储型

  • 安全组：虚拟防火墙，默认放行内部、控制外部访问，是实例级、有状态（后面网络部分细讲）

  • 计费：

    按需 = 随时开随时关（贵）

    包年包月 = 长期租（便宜）

    竞价 = 超便宜但可能被收回

  • 远程登录 ECS 走 SSH（端口 22）

3.AS

  • 伸缩组：把一批 ECS 圈在一起管理（比如 “3~10 台”）

  • 伸缩配置：新加的机器用什么镜像、什么规格（提前定好模板）

  • 伸缩策略：什么时候加、什么时候减，分三种

    定时：定好 “每天 20 点加 2 台，23 点减 2 台”，用于规律性流量（晚高峰）

    周期：按星期几循环执行，用于周末 / 工作日差异

    动态（告警）：监控 CPU 使用率 > 80% 就加，< 30% 就减，用于流量突增突降（最常用）

  • 健康检查：AS 定期检查每台 ECS 是否 “活着”，挂了就自动移除并新建一台顶上。

总结：

  1. ECS 属于 IaaS；镜像可以批量创建 ECS；安全组默认放行内部、控制外部访问。
  2. AS = 削峰填谷、控制成本；配合 ELB 用；健康检查失败的实例自动替换。
  3. ELB 支持四层 + 七层；调度算法 = 加权轮询 / 最少连接 / IP Hash；IP Hash 用于会话保持；健康检查自动摘除故障后端。

三件套怎么配合

存储服务三件套

存储类型 怎么理解 类比
块存储 按 “块”（小格子）读写，最快，但一块盘只能给一台机器用 电脑里的硬盘
文件存储 按 “文件夹路径” 读写，多台机器能同时用 公司共享文件夹
对象存储 按 “钥匙（URL）” 读写，容量几乎无限，管海量文件 网盘

EVS 云硬盘

是什么：

EVS 就是给 ECS 当硬盘用的

关键考点

  1. 必须挂载到 ECS 才能用：EVS 不能独立存在，它依赖 ECS
  2. 默认只能挂一台 ECS：普通云硬盘同一时刻只能被一台 ECS 使用（所以叫 “块存储”）
  3. 低延迟、高性能：数据库这类对速度敏感的场景首选 EVS
  4. 快照：某个时间点的 “拍照备份”，数据坏了能一键还原到拍照那一刻
  5. 可以扩容、可以备份：数据盘随时扩容量；配合备份服务做容灾
  6. 磁盘类型：普通 IO、高 IO、超高 IO
  7. 共享云硬盘最多同时挂载 16 台 ECS
  8. 可扩容的状态：可用、正在使用
  9. 删除条件：未被其他服务占用才能删

SFS 文件存储

是什么：

共享储存，大家都能往里面放文件、读文件。

关键考点

  1. 多台 ECS 共享：跟 EVS”一块盘一台机” 相反，SFS 天生就是给大家一起用的
  2. 按目录层级访问：像 /data/user1、/data/user2 这种路径方式读写
  3. 访问协议：NFS（Linux 用）、NFSv3、NFSv4、CIFS（Windows 用）
  4. 典型场景：大数据分析（多台计算节点共享数据）、媒体处理、容器共享存储
  5. 访问时不占用 ECS 本地磁盘，数据都在云上
  6. 监控：用 CES 云监控 监控文件系统性能指标

OBS 对象存储

是什么：

基于对象的海量存储

网盘，容量几乎无限，存图片、视频、日志、备份**都往这里放。

两个核心概念（必考）

  • 桶（Bucket）：存储空间的 “容器”，像网盘里的 “根目录”。用 OBS 前必须先建桶

    桶策略三种：私有、公共读、公共写

  • 对象（Object）：一个文件就是一个对象，每个对象有个唯一的 “钥匙”（URL）

    对象组成部分：Key（对象名）、Metadata（元数据）、Data（数据）**

怎么访问：用 AK/SK（Access Key / Secret Key，类似 “账号密码”）认证，通过 API / SDK / 控制台上传下载。

存储类别：标准、低频访问、归档三种

权限控制方式：IAM 权限、桶策略与对象策略、ACL

ACL 被授权用户：拥有者、注册用户组、日志投递用户组

生命周期管理：标准→低频、标准→归档、过期删除

访问方式：OBS Browser+（图形客户端）、API & SDK、obsutil（命令行）、obsfs（文件系统挂载）**

优点：

  1. 海量 + 按量计费：不用预估容量，用多少付多少，成本可控
  2. 高持久性：华为云宣传数据持久性 99.999999999%
  3. 分级存储：热数据选择 “标准”（快）、冷数据选择 “低频 / 归档”（便宜）

典型场景

  • 网站图片、视频、静态文件 ，HPC、电影剪辑（还能做静态网站托管）
  • 数据库备份、日志归档
  • 大数据分析前的原始数据存放 → 可以 OBS 也可以 SFS（看是否要共享给多台机器）

总结

  • EVS = 云硬盘 = 块存储，挂 ECS 用，低延迟，快照 = 时间点备份。
  • SFS = 文件存储 = 共享文件夹，多机同时挂载，按路径访问。
  • OBS = 对象存储，桶 + 对象，AK/SK 认证，海量 / 按量 / 高持久，备份和静态网站首选

网络服务

VPC 虚拟私有云

是什么：

在华为云上给划一块完全私有的网络空间，ECS 都在这里。内部可通信，外部默认隔离—— 这就是 VPC 的隔离性。

概念 解释 考点
子网（Subnet） 把网络再分子网（Web 一个网段、数据库一个网段 子网按网段划分，便于分层管理
CIDR IP 地址段的写法，如 192.168.0.0/16 /16 表示网段大小；规划 VPC / 子网要先定 CIDR
路由表 子网内网络流量走向的规则集合，包含目的地址段和下一跳 每个子网关联一张路由表
EIP 弹性公网 IP 给 ECS 一个公网 IP，让外面访问 可以绑定 / 解绑，随时换
NAT 网关 内网机器偷偷上网，但不暴露自己的 IP 内网访问外网、隐藏内网机器

重点

  1. 默认隔离：不同 VPC 之间默认不能互通（要互通需用对等连接 / 云连接）
  2. 子网默认互通：同一个 VPC 里的子网之间默认可以通信
  3. 内网 / 外网：公网访问要配 EIP；内网互访走私有网段

细节：

EIP 弹性公网 IP

  • 按需计费的 EIP：独享带宽可以转共享带宽
  • 包年包月的 EIP：独享带宽不能转共享带宽
  • EIP 是静态公网 IP（不是动态 IP）
  • 一个 EIP 绑定一个 ECS（不能多个 ECS 共用）

安全组 & 网络 ACL

是什么：

安全组是每台 ECS 的防火墙：看规则决定 “放哪个端口进来（比如 80/443）”。

网络 ACL 是整个子网的防火墙：先过这关，再进ECS。

对比：

对比项 安全组（SG） 网络 ACL
负责对象 实例级（绑在 ECS 上） 子网级（管整个子网）
状态 有状态 无状态
规则方向 入方向 + 出方向 入方向 + 出方向（都要单独配）
放行逻辑 全部规则取 “或”（任一放行就过） 按优先级从高到低匹配，可拒绝
应用顺序 先过安全组，再过 ACL（或反之按架构） 两道都要过

有状态 vs 无状态”

  • 有状态（安全组）：从里面发出去的请求，回来的响应包自动放行，不用再配入站规则。像保安记住 “你刚出门了，回来自动放行”
  • 无状态（网络 ACL）：出去的规则、进来的规则都必须配置。

默认规则（华为云）

  • 安全组：出方向默认放行，入方向默认拒绝（要手动加规则放行指定端口）
  • 新建安全组时通常先配好常用端口（SSH 22、RDP 3389、HTTP 80/443）

专线 DC

是什么：

拉一条物理专线，把本地机房和云上 VPC 直接连起来，不经过公共互联网。

专线 vs VPN:

对比项 专线 DC VPN（走公网）
通道 专用物理线路 公共互联网 + 加密隧道
时延 / 带宽 低时延、高带宽 受公网影响
稳定性 / 安全 稳定、安全 一般
成本 贵（按带宽 / 端口收费） 便宜
场景 核心业务、混合云 临时 / 预算有限

典型场景：混合云（本地数据中心 + 云上 VPC 协同）、核心系统迁移上云、两地容灾。

总结

VPC = 云上私有网络（默认隔离），CIDR 定网段，子网分层，EIP 对外、NAT 内网上网。

安全组 = 实例级 + 有状态；网络 ACL = 子网级 + 无状态；安全组入方向默认拒绝。

专线 = 专用物理连接，低时延高带宽但贵；VPN = 公网加密隧道，便宜但看公网好坏。

容器与云原生

Docker

是什么：

把应用 + 它需要的环境一起打包成一个 镜像，搬到任何机器上都能跑，环境永远一致

组成：

  • 镜像（Image）：只读的模板文件，包含应用代码、运行时、依赖库与配置
  • 容器（Container）：镜像的运行实例，可启动 / 停止 / 删除；多个容器共享宿主机内核
  • 仓库（Registry）：存储与分发镜像的地方（如 Docker Hub、华为云 SWR）
  • 容器技术本质：操作系统级虚拟化，通过命名空间（Namespace）隔离进程 / 网络 / 文件系统，通过 Cgroups 限制资源
  • Dockerfile：以文本方式定义如何构建镜像（自动化构建）

Kubernetes（K8s）

是什么：

当容器成千上万的时候，人管理起来麻烦，可配置K8s 全自动管理。它就是容器编排平台

组成：

  • Pod：Kubernetes 的最小调度单元，一个 Pod 内可运行一个或多个容器（共享网络和存储）
  • Node：工作节点，运行 Pod 的机器
  • 控制面（Master）：集群的大脑，含 API Server（入口）、Scheduler（调度）、etcd（集群状态存储）
  • Deployment：声明期望的副本数，负责滚动更新与回滚
  • Service：为 Pod 提供稳定的虚拟 IP 和负载均衡入口（Pod IP 会变，Service 不变）
  • 自愈能力：健康检查失败 → 自动重启或重建 Pod
  • 弹性伸缩：根据负载自动增减 Pod 副本（HPA）

CCE 华为云容器引擎

自己搭 K8s 集群：要装 master、配 etcd、维护升级，很累。CCE 就是华为云帮你把 K8s 集群装好、管好的服务，你只管部署应用

  • CCE（Cloud Container Engine）：基于 Kubernetes 的容器托管服务
  • 提供集群创建、节点管理、弹性伸缩、日志监控
  • 与华为云 VPC、EVS/SFS、ELB、IAM 等原生集成
  • 支持混合云 / 多云场景，一键部署容器化应用

云原生

云原生是以容器、微服务、DevOps、持续交付和声明式基础设施为核心的应用理念 —— 应用从设计之初就 “为云而生”。容器化是云原生的基础之一。

总结

  • 镜像 = 只读模板，容器 = 运行实例；容器共享宿主机内核，所以比虚拟机轻量。
  • Pod 是最小调度单元；K8s 负责容器的编排、调度、自愈与伸缩；Deployment 管副本，Service 管访问入口。
  • CCE = 华为云托管的 Kubernetes 服务；K8s 是技术，CCE 是 “开箱即用” 的云产品。

数据库服务

RDS 关系型数据库服务

RDS 就是把 MySQL / PostgreSQL / SQL Server / MariaDB 装好、管好给你用，托管式关系型数据库服务。

支持引擎：MySQL、PostgreSQL、SQL Server、MariaDB

托管能力（考点）：

  • 主备高可用：一主一备，主库故障自动切换到备库，业务无感知

  • 自动备份：按策略定时备份，可一键恢复到任意备份点

  • 只读实例：主库只管写，再挂几台 “只读副本” 专门应付读，分担主实例读压力，实现读写分离

    同步延迟：复制是异步的，只读实例数据可能比主实例滞后几秒 → 对实时性要求极高的数据（如刚下的订单立刻要读到）不适合走只读

  • 监控告警、参数调优、存储扩容

部署形态：单机（便宜）/ 主备（高可用，推荐生产）

GaussDB 高斯数据库

华为自研的 “国产数据库”

GaussDB：华为自研的关系型数据库产品系列

常见形态：

  • **GaussDB(for MySQL)**：兼容 MySQL 协议 / 语法，性能与扩展性更强
  • **GaussDB(for openGauss)**：基于 openGauss 开源内核，强一致、金融级
  • GaussDB (for Redis)、GaussDB (for Mongo) 等：对应 NoSQL 场景

特点：高可用、强一致性、分布式扩展、金融级安全

场景（考点）：国产化 / 信创替代、金融核心系统、政企大数据库

RDS vs 自己在 ECS 上装数据库

对比项 RDS 托管 ECS 自建（如自己装 MySQL）
部署 一键开通，开箱即用 自己装、自己配
高可用 自动主备切换 自己搭主从、自己切换
备份 自动备份 自己写脚本
运维 云厂商负责 自己
灵活性 较低（受平台限制） 高（完全可控）
成本 含服务费 便宜（但人力成本高）

NoSQL

非关系型数据库：DDS（文档数据库服务，兼容 MongoDB）、GaussDB (for Redis) 等

特点：灵活 schema、海量存储，适合 JSON 文档、缓存、时序等场景

考点：题目给场景 ——“存结构不固定的 JSON 文档” → 文档数据库（MongoDB/DDS）

DDM 分布式数据库中间件

  • 大白话：数据库 “拆表分片” 的管家 —— 把一张大表拆到多个数据库上，对外还是一个 “数据库”
  • 专业版：DDM（Distributed Database Middleware），解决数据库水平扩展和海量数据存储问题
  • 考点：问 “水平扩展 / 海量存储” → DDM（不是 RDS）

IMS 镜像服务

ECS 要靠镜像装系统。IMS 就是管镜像的服务：自己做的模板（私有镜像）能共享给别人、也能用快照 / 云备份做新镜像。

  • IMS（Image Management Service）：镜像管理服务，管公共镜像、私有镜像、共享镜像三类（无 “私密镜像”）
  • 考点：
    • 私有镜像可以共享（给同租户的其他用户 / 其他区域）
    • 整机镜像的镜像源：云服务器、云服务器备份、云备份、ISO 镜像
    • 可以做磁盘快照（快照→创建私有镜像）

BMS 裸金属服务器

ECS 是 “虚拟出来” 的机器，BMS 是直接给你一台真物理机

  • BMS（Bare Metal Server）：裸金属服务器，独享物理机资源，无虚拟化开销
  • 支持的网络类型（必背）：虚拟私有云（VPC）、高速网络、IB 网络（InfiniBand）、自定义 VLAN

适用：高性能计算、数据库、对性能 / 安全要求极高的场景

CBR 云备份服务

CBR 是华为云统一的 “备份保险柜”：把云服务器、云硬盘打包备份，出事了能恢复。

  • CBR（Cloud Backup and Recovery）：云备份服务，备份对象 = 云服务器、云硬盘
  • 备份类型：默认策略下首次全量备份，后续增量备份（只备份变化的部分）—— 不是 “差异备份”
  • 存储库类型（必背）：备份存储库、复制存储库、归档存储库（无 “标准存储库”）
  • 恢复方式：云服务器备份恢复、云硬盘备份恢复、混合云备份恢复（无 “OBS 备份恢复”）
  • 跨区域复制条件：备份由 ECS/EVS 产生、包含系统盘、备份状态为 “可用”（不用 “由 OBS 产生”）
  • 备份过程中自动创建快照并保留 —— 正确

AI 与机器学习基础

包含关系：深度学习 ⊂ 机器学习 ⊂ 人工智能

机器学习定义：从数据中自动学习模型参数，对新数据做出预测或决策，无需显式编程规则

深度学习：基于多层人工神经网络（Deep Neural Network）的表示学习方法，自动从数据中提取多层特征

三种学习方式

1）监督学习（Supervised Learning）

  • 大白话：有标准答案（标签）的教学 —— 老师把 “这是猫” 标好，机器照着学
  • 专业版：训练数据带标签（Label），学习输入到输出的映射
  • 两大任务（必考）：
    • 分类（Classification）：输出离散类别 → 垃圾邮件判断、猫狗识别
    • 回归（Regression）：输出连续数值 → 房价预测、气温预测
  • 常见算法：逻辑回归、决策树、随机森林、SVM、KNN

2）无监督学习（Unsupervised Learning）

  • 大白话：没有标准答案—— 一堆数据丢给你，自己找规律、自己分组
  • 专业版：训练数据无标签，发现数据内在结构
  • 核心任务：聚类（Clustering）（K-Means 用户分群）、降维（PCA）
  • 考点：K-Means 是无监督聚类算法

3）强化学习（Reinforcement Learning）

  • 大白话：做对给糖、做错挨罚—— 智能体通过试错学策略
  • 专业版：智能体（Agent）与环境交互，依据奖励信号（Reward）调整策略，目标最大化累计奖励
  • 场景：AlphaGo、自动驾驶、游戏 AI
  • 考点：”AlphaGo 属于强化学习” → 正确

关键概念

概念 大白话 专业版
特征（Feature） 判断用的线索（猫的耳朵、胡须） 输入数据中用于预测的属性维度
标签（Label） 标准答案（”这张图是猫”） 监督学习中样本的真实输出
训练集 / 测试集 复习题 / 考试题（不能偷看答案） 训练模型 vs 评估泛化能力的数据集
过拟合 Overfitting 背题背太死，换道题就不会 模型在训练集表现好、测试集差，泛化能力弱
欠拟合 Underfitting 学太少，啥也没学会 模型太简单，训练集都学不好

过拟合（最高频的坑，记住）

  • 表现：训练集准确率高，测试集 / 新数据准确率低
  • 原因：模型太复杂、数据太少、训练太久
  • 对策：更多数据、正则化、简化模型、早停

深度学习核心

  • 神经网络：一堆 “神经元” 分层连接，每层提取不同层次特征
  • CNN（卷积神经网络）：图像王者 —— 用卷积核提取局部特征（边缘、纹理→形状→物体）
  • RNN / LSTM（循环神经网络）：处理序列—— 文本、语音、时间序列（记上下文）
  • Transformer：大模型（ChatGPT 这类）的基础架构
  • 训练三要素：数据 + 算力 + 算法

提示工程

三个采样参数：

参数 作用 考点
温度 Temperature 控制输出随机性：越高越随机 / 有创意，越低越确定 / 保守 控制 “随机性”，不是训练速度 / 准确性
Top_k 只从概率最高的 k 个 token 里选：k 越大候选越多 “k 越大，选择 token 数量越多” ✅；”k 越小越随机” ❌（越小越确定）
存在惩罚 Presence Penalty 对已出现的 token 施加负向惩罚，减少重复 值域 -2.0 ~ 2.0；影响生成概率分布

Tokenizer

  • Tokenizer（分词器）：把输入文字切分成 Token（词元）→ 模型读的 “单词卡片”
  • DeTokenizer（逆分词）：把 Token 拼回完整文本
  • LLM 推理流程（必背顺序）：Tokenization → Sampling（采样）→ DeTokenization → Output Formatting（输出格式化）

提示技巧三件套

技巧 大白话 专业定义
零样本 Zero-shot 直接下指令，不给例子 不提供示例直接生成
少样本 Few-shot 先给几个例子再提问 通过少量示例帮助模型理解任务（= 样本提示 Sample Prompting）
思维链 CoT 让模型 “一步步想” 依赖模型自身逐步分解问题并分析，而非直接给答案
RAG 检索增强生成 先查资料再回答 结合检索信息与模型生成回答；标准流程 =先检索知识库，后生成输出

RAG 三大必背结论

  • 流程：先检索 → 后生成
  • 不修改大模型底层权重与参数
  • 缓解大模型幻觉的核心手段：RAG 知识库约束、结构化 Prompt、知识库定期更新

盘古应用开发套件

  • 开发模式：轻量化编排、全流程编排、代码开发
  • 基础语言模型的局限：没有明确的目标导向（需要提示词 “派活” 才能干活）

预训练、微调与数据工程

  • 预训练 Pre-training：在海量无标注通用语料上训练，形成基础语言能力与通用知识
  • 训练大模型的三大依赖：参数规模、高性能计算设备、长时间计算

微调的三种打开方式

方式 说明

SFT 监督微调 依托人工标注的 instruction-input-output 样本，以拟合标准答案为目标；可搭配全量或 PEFT

大数据服务

数据 4V 特征（记首字母）

  • Volume 海量：数据量大
  • Velocity 高速：产生 / 处理快（实时流）
  • Variety 多样：结构化 + 非结构化（文本、图片、日志）
  • Value 价值：低价值密度，但挖掘出大价值

两种处理模式

  • 批处理（离线）：积攒一批数据统一算（T+1 报表）
  • 流处理（实时）：数据边到边算（实时告警、实时风控）

MRS

  • 华为云托管式大数据集群服务，基于开源 Hadoop 生态
  • 内置组件：HDFS（分布式文件系统）、MapReduce、Spark、Hive、Flink、HBase、Kafka 等
  • 能力：快速创建集群、弹性伸缩、与 OBS 打通（存算分离：数据放 OBS，计算用集群）
  • 适合：有大数据开发能力，需要 Spark/Hive/Flink 做自定义数据处理

DLI（数据湖探索）

不想建集群、不想管服务器？DLI 是无服务器（Serverless）的：你把数据放好，直接写 SQL 就能查，用多少算多少的钱。

  • 核心特点：Serverless（无需预置 / 管理集群）、支持 SQL 分析（兼容 Spark SQL、Flink SQL）
  • 支持批处理 + 流处理：既可跑离线 SQL，也可做实时流分析
  • 计费：按扫描的数据量计费（用了才付钱）
  • 适合：中小团队、不想运维集群、快速 SQL 分析

考点：DLI 关键词 = Serverless + SQL + 按量计费；不用自己建集群。

DWS（数据仓库服务）

普通数据库（RDS）管 “日常交易”（下单、转账），DWS 管 “大规模分析”（这个季度卖了多少、哪个地区增长最快）。它是专门为报表、BI 分析设计的。

  • 定位：在线分析处理（OLAP），面向复杂查询、报表、商业智能（BI）
  • 内核：基于 PostgreSQL（即 GaussDB (DWS)）
  • 特点：行列混合存储、列存加速分析、高并发、可扩展
  • 对比：RDS = OLTP（事务处理，增删改查）；DWS = OLAP（分析处理，复杂查询聚合）

考点（高频）：

  • DWS 属于 OLAP，RDS 属于 OLTP
  • 问 “报表 / BI / 大数据分析” → DWS
  • DWS 基于 PostgreSQL 内核

安全服务

WAF Web 应用防火墙

  • WAF（Web Application Firewall）：部署在 Web 应用前面（反代模式），检测并拦截恶意请求
  • 防护能力（考点列举）：
    • SQL 注入：在输入框 / URL 塞 SQL 语句窃取数据库
    • XSS 跨站脚本：往页面注入脚本盗取用户信息
    • 恶意爬虫、CC 攻击、网页篡改、暴力破解
  • 部署位置：可与 CDN、ELB 组合，云 WAF / 独享 WAF
  • 对应层级：应用层（OSI 第 7 层）

考点：问 “防 SQL 注入 / XSS 用什么” → WAF；WAF 是应用层防护。

DDoS 高防

  • DDoS（Distributed Denial of Service）：分布式拒绝服务，利用大量傀儡机并发攻击耗尽目标资源，导致正常用户无法访问
  • 华为云 Anti-DDoS：默认基础防护免费（自动流量清洗）
  • DDoS 高防（高防 IP）：付费扩容，可抗超大流量（几十 Gbps 级），通过流量清洗 / 黑洞机制
  • 防护能力：流量型攻击（SYN Flood、UDP Flood、CC 等）

考点：

  • DDoS = 流量型攻击（把服务打瘫）
  • WAF = 应用型攻击（SQL 注入 / XSS）—— 两者别混
  • Anti-DDoS 基础防护免费，高防付费

堡垒机 CBH

  • 堡垒机（Cloud Bastion Host，CBH）：运维安全审计服务
  • 核心能力：
    • 统一入口：所有运维操作从堡垒机进入
    • 身份认证：支持双因子认证
    • 权限控制：按最小权限授权，高危命令阻断
    • 操作审计：全程录屏 / 日志留存，可追溯
  • 价值：满足等保合规、防止越权与误操作、事后审计追溯

考点：问 “运维登录唯一入口 + 审计录像” → 堡垒机；”高危命令阻断” 也是堡垒机能力。

AlexNet 2012・Geoffrey Hinton 团队 GPU 加速训练、ImageNet 分类准确率显著提高、数据增强、验证深度网络潜力 深度学习 “引爆点”
Word2Vec Google 生成词向量；在百万级词典 / 上亿数据上高效训练；低计算成本下显著提升精度；能度量词间相似性 不是 “训练成本极高”
ResNet 2015 残差连接，解决深度网络退化问题（网络越深反而不如浅层） 注意：退化 ≠ 梯度消失（ResNet 也缓解梯度问题，但题目问 “主要解决” 选退化）
BERT Google 双向 Transformer，刷新多项 NLP 记录 双向
GPT-1 OpenAI 首次验证 “预训练 + 微调” 范式 第 9 套第 6 题答案 = GPT-1
GPT-3 OpenAI 应用：Copilot 代码生成、Jasper 文案创作 不含 “自动驾驶控制 / 视频生成”
DeepSeek R1 2025 推理模型：AIME2024、Codeforces、MATH500 胜过 OpenAI o1 推理 + 开源 + 数学 / 代码强

Transformer

  • 《Attention Is All You Need》由 Google 团队提出，首次引入自注意力机制替代传统 RNN
  • 核心创新四件套：多头注意力机制、位置编码、前馈网络层、残差连接

自注意力优势：支持并行计算 + 捕捉长程依赖

对后续影响：奠定 BERT 基础、GPT 系列相继采用、推动 Transformer-XL 发展

对比组 分辨口诀
ECS vs 容器 vs VM ECS = 云上虚拟机（IaaS）；容器共享内核更轻量
EVS / SFS / OBS 硬盘 / 共享文件夹 / 网盘
镜像 vs 快照 镜像 = 模板，快照 = 时间点备份
ELB 四层 vs 七层 四层转包裹，七层拆包裹
调度算法 轮询 = 轮流，最少连接 = 谁闲给谁，IP Hash = 固定找同一个人
安全组 vs 网络 ACL 有状态（回包自动放行）/ 无状态（各配各）
专线 vs VPN 专用公路（稳贵）/ 公网加密（便宜）
RDS vs DWS OLTP 事务 / OLAP 分析
MRS / DLI / DWS Hadoop 集群 / Serverless SQL / 数仓
SMS / OMS / DRS 服务器 / 对象数据 / 数据库
WAF vs DDoS 拦聪明攻击（注入）/ 扛粗暴攻击（流量）
昇腾 / MindSpore / ModelArts 芯片 / 框架 / 平台
Runbook / Landing Zone 操作手册 / 上云前环境规划
